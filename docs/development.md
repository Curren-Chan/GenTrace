# GenTraceの開発と検証

通常の構成説明と操作方法は [README](../README.md) が正本。この文書は変更内容に関係する節だけ読む。

## 自動テスト

プロジェクト直下で既存の `run_tests.cmd` を実行する。別のPythonを明示する場合も、同じテスト群を使う。

```powershell
python -m unittest discover -s tests -v
```

通常ユーザー環境では2026-09-14にPython 3.11.9を確認した。PATHや依存関係は変更せず、作業環境の実際の実行ファイルを確認する。READMEの対象バージョンを依存関係の現状と取り違えない。

テストは一時DB・画像とローカルの模擬HTTPサーバーを使う。GPUカウンターの読取テストを含むが、本番の画像生成は行わない。依頼に伴うこのテストと、依頼した変更が原因の修正・再検証は追加確認なしで進めてよい。

## DB・CSV・画像参照を変更するとき

- 関連コードは `gentrace/database.py`、`csvexport.py`、`records.py`。収集変更では `collector.py` と対応するテストも確認する。
- スキーマ変更は既存データを保持し、旧構成からの移行を使い捨てDBで検証する。旧CSVの列順・意味を維持する。
- `outputs.file_path` は絶対パス。参照先が消えてもログを消さず、未記録の画像パスやLoRA情報は不明のまま扱う。
- Loggerに画像の複製・移動・削除・サムネイル・常時ファイル監視を追加しない。
- SQLiteの稼働中バックアップを求められた場合はOnline Backup APIを検討する。WAL使用中のDB単独コピーや、未依頼のVACUUM・削除を検証に含めない。

## UI・実環境を確認するとき

- `tests/test_gui.py` は表示幅・更新条件のヘルパーテストで、画面操作の証明にはならない。`tests/test_filedrop.py` はWindowsの実際のTkウィンドウへドロップ通知を送る統合検証で、本番設定へ依存しない。
- UI変更時は変更した操作を確認する。画像参照なら、残存画像・欠損画像・未記録パスの状態を一時データで用意する。本物の画像を削除して試さない。
- 実生成確認が依頼に含まれる場合だけ、利用可能なバックエンドで新しいジョブと出力パスの保存まで確認する。APIが停止中なら自動テスト成功と実生成未確認を分けて報告する。
- `diagnose.py` は `Database.initialize()` を呼ぶため、読み取り専用監査では実行しない。`tests/manual_gui_preview.py` も通常の自動テストには含めない。
